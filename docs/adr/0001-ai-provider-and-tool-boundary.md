# ADR 0001：模型供应商与只读工具边界

状态：已采纳（Stage 2A）

## 决策

诊断通过 `ModelGateway` 选择 `deterministic`、`openai-compatible`、`ollama` 或 `manual-only`。确定性适配器用于可重复的 Demo/Eval；生产 profile 禁止选择它。模型缺失或不可用时进入显式失败或人工模式，不把规则输出冒充真实模型判断。

服务端只注册 `queryMetrics`、`queryLogs`、`getEvidence`、`searchRunbooks` 四个只读工具。事故、服务、运行 ID 和 15 分钟证据窗口由服务端冻结；工具参数只包含预登记 query ID 或证据 ID，不能传入任意 URL、PromQL、LogQL 或执行命令。每次诊断最多 6 次调用、90 秒，输入/输出字节和来源响应也有独立上限。来源结果标为不可信，并经脱敏、规范化和哈希后才可保存、引用或交给模型。

模型输出只是提案。`DiagnosisPolicy` 再次验证证据引用、服务范围、已发布 Runbook 版本、参数、风险级别和恢复探针。批准与执行是另外的事务和角色边界；诊断工具不能直接改变目标系统。运行保存模型、prompt、工具集合、语料版本、哈希、用量和调用次数，不保存原始 prompt、密钥或完整工具结果。离线 Eval 通过模型工厂打开独立会话，只使用数据集内的证据、Runbook 和检索 fixture；即使 Demo 在线证据模式为 `real`，也不能访问或写入在线事故证据。

## 原因与后果

这一边界让供应商更换不改变事故状态机，也让提示注入只能进入不可信证据正文。确定性规则可以测量接口和安全退化路径，但不能证明在线模型的语义质量。真实供应商仍需固定模型 snapshot/tag、单独 Eval 和可选烟测；凭据只通过环境引用解析。
